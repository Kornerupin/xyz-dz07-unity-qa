# ДЗ 7 Автоматическое тестирование Unity и ИИ анализ ошибок

Учебный проект Echoes of Ascent из архива курса. Подготовлен для **Unity 6000.4.0f1**. Начать работу: [пошаговая инструкция](DZ07_START_HERE.md).

В `.github/workflows/ai_qa_gate.yml` настроен запуск по `push`: локальные проверки анализатора, все EditMode и PlayMode-тесты через GameCI, проверка результатов. После подтверждённого падения теста условие `failure()` запускает отдельную job с локальной моделью Qwen через Ollama. Ключ OpenAI и платный API не требуются; модель работает на CPU GitHub runner. Настоящий статус failed из XML переносится в job анализа, поэтому создание Issue также защищено условием `failure()`. Issue создаётся только после успешного ответа нейросети, проверки цитат и принадлежности результата текущему commit, run и run attempt. Ошибка теста сохраняет красный статус запуска. Логи и результаты анализа выгружаются в артефакт `qa-evidence-*`.

В исходном архиве `CraftTest` был постоянно падающей демонстрацией. Здесь он проверяет небольшой класс `CraftingRules`: меч расходует 2 дерева и 3 железа. Из запаса 5/4 остаётся 3/1; при нехватке ресурсов инвентарь не меняется. Остальные игровые тесты сохранены.

```powershell
.\tools\check-local.ps1
.\tools\set-craft-state.ps1 broken
.\tools\set-craft-state.ps1 green
```

`broken` меняет только ожидаемый остаток дерева с 3 на 4, `green` восстанавливает 3. Каждый этап нужно отправить отдельным коммитом и дождаться результата Actions согласно инструкции.

Локально проверены 28 Python-тестов и 7 тестов JavaScript. Класс крафта дополнительно скомпилирован и выполнен в .NET: четыре сценария проходят; ожидание 4 даёт ошибку. Это локальная проверка чистой C#-логики, а не запуск Unity. Полный Unity-прогон, обращение к API и создание Issue выполняются после публикации и настройки секретов.

Дополнительная C#-проверка при установленном .NET SDK 10:

```powershell
dotnet run --project tools/CraftLogicSmoke/CraftLogicSmoke.csproj -- 3
```

Учебные профили Cursor сохранены в `Docs/cursor-agent-kit`; пути адаптированы в `PROJECT.md`. Они служат справочными материалами и автоматически не активируются.

Основной результат для сдачи: публичная ссылка на автоматически созданный Issue и доступные зелёный и красный прогоны GitHub Actions. Исходники сами по себе не подтверждают выполнение внешних этапов.
