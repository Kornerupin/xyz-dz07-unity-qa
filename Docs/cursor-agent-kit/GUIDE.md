# Cursor Agent Profiles — простой гайд

Kit лежит в папке `Docs/cursor-agent-kit/`.  
PDF открывайте в Edge / Adobe / Chrome (в Cursor PDF выглядит как «кракозябры» — это нормально).

---

## Перед стартом (один раз на проект)

1. Скопируйте папку `cursor-agent-kit` в свой репозиторий.
2. Скопируйте `PROJECT_CUSTOMIZATION.template.md` → сохраните как `PROJECT.md`.
3. Заполните в `PROJECT.md` пути к коду, тестам, CI и командам своего проекта.
4. В Cursor включите нужный профиль (см. раздел QA или Developer ниже).

Дальше агент берёт пути из `PROJECT.md`. Сами skills/rules трогать не обязательно.

---

# Часть A — QA

## Зачем

Писать и чинить автотесты, ревьюить тестовые PR.

## Что включить в Cursor

Скопируйте содержимое:

- `profiles/qa/rules/` → `.cursor/rules/`
- `profiles/qa/skills/` → `.cursor/skills/`

(Перед сменой роли очистите эти две папки `.cursor`, чтобы не смешать QA и Developer.)

## Когда что использовать

| Задача | Что сделать |
|--------|-------------|
| Написать новые тесты | Вставить в чат файл `profiles/qa/playbooks/write-tests.md` (в первой строке `{…}` напишите задачу) |
| Починить падающие / флаки | Вставить `profiles/qa/playbooks/fix-tests.md` |
| Упорный флак / красный CI | Вставить `profiles/qa/playbooks/refresh.md` |
| Ревью тестов | Вставить `profiles/qa/playbooks/review.md` |
| Итог сессии → обновить правила | Вставить `profiles/qa/playbooks/retro.md` |

Можно вместо вставки просто написать в чат то же самое («напиши автотесты на …») — skills подхватятся сами, если профиль включён.

## Skills у QA

| Skill | Для чего |
|-------|----------|
| `write-autotests` | Новые тесты |
| `fix-autotests` | Починить тесты |
| `qa-code-review` | Ревью тестов |
| `deep-rca-test-failures` | Глубокий разбор упорных падений |
| `retrospective-doctrine-evolution` | Обновить правила после сессии |

## Правила QA (кратко)

- Сначала найти похожие тесты, потом писать новые.
- Сначала воспроизвести падение, потом чинить.
- Не удалять assert, чтобы «позеленело».
- Не прятать боевые тесты под demo/skip-категорию из `PROJECT.md`.
- Юнит — для логики; интеграция/E2E — для рантайма/UI.

# Часть B — Developer

## Зачем

Фичи, багфиксы, ревью перед мержем.

## Что включить в Cursor

Скопируйте содержимое:

- `profiles/developers/rules/` → `.cursor/rules/`
- `profiles/developers/skills/` → `.cursor/skills/`

(Перед сменой роли очистите `.cursor/rules` и `.cursor/skills`.)

## Когда что использовать

| Задача | Что сделать |
|--------|-------------|
| Новая фича / рефактор | Вставить `profiles/developers/playbooks/request.md` (в `{…}` — задача) |
| Упорный баг | Вставить `profiles/developers/playbooks/refresh.md` |
| Ревью перед мержем | Вставить `profiles/developers/playbooks/review.md` |
| Итог сессии → обновить правила | Вставить `profiles/developers/playbooks/retro.md` |

## Skills у Developer

| Skill | Для чего |
|-------|----------|
| `feature-implementation` | Фича / рефактор по фазам |
| `deep-rca-remediation` | Глубокий RCA бага |
| `pre-merge-code-review` | Ревью перед мержем |
| `retrospective-doctrine-evolution` | Обновить правила после сессии |

## Правила Developer (кратко)

- Сначала разобраться в коде, потом менять.
- Маленькие диффы; править всех потребителей изменённого контракта.
- Не коммитить секреты.
- Большие кампании по автотестам — отдать QA-профилю.

## Что править под свой проект

| Нужно изменить | Файл |
|----------------|------|
| Пути, CI, команды, нейминг тестов | `PROJECT.md` |
| Тон / жёсткие запреты | `profiles/.../rules/` |
| Сценарии работы агента | `profiles/.../skills/` |
| Текст «вставь в чат» | `profiles/.../playbooks/` |

В файлах есть пометки **CUSTOMIZE** — это подсказки, что можно заменить.

---

## Частые проблемы

| Проблема | Решение |
|----------|---------|
| Агент ведёт себя не по QA/Dev | Не скопирован профиль в `.cursor/` или смешаны оба |
| Путает папки проекта | Не заполнен `PROJECT.md` |
| Playbook «не работает» | Его нужно **вставить в чат целиком** |
| PDF «сломан» в Cursor | Открыть во внешнем просмотрщике |
